## 共通の約束

### パッケージと依存
- 依存の向き(CLAUDE.md、`tests/test_dependencies.py`)を守る。editor と viewer の両方で使うもの
  (Host の検査、上書きしない書き込み、ffmpeg による変換)は `music_io` に置く。
  発音時刻の候補の計算は `piano_transcribe` に置く。editor から `performance_analysis` は呼ばない
- 新しい依存は増やさない(numpy と標準ライブラリで書く)。ffmpeg は外部コマンドとして呼び、
  なければ「ffmpeg が必要です(brew install ffmpeg)」と画面に出す。WAV だけならなくても動くこと
- コメントと画面・出力の文言は日本語

### 出力ファイル(無断で上書きしない)
- **元からあるファイルは、確かめずに上書きしない。** 対象は、入力の録音・楽譜、書き出し先にすでにある MIDI・WAV・HTML、
  プロジェクトの外のすべてのファイル。入力の録音と楽譜は、どんな場合も書き換えない(読むだけ)
- 書き出し先にファイルがあれば、サーバーは書かずに 409 を返す。返す内容は、すでにあるファイルのパス・大きさ・更新時刻と、
  空いている別名(`名前-2.mid` など)。画面では「別名で保存 / 上書き / やめる」を選ばせる。
  上書きは、画面で選んだときだけ要求に `overwrite: true` を付けて行う
- プロジェクトのフォルダ(`<projects>/<名前>/`)の中で editor 自身が作るファイル(project.json、model.npz、
  score.xml、meta.json、<名前>.mid)は、保存の操作で更新してよい。ただし:
  - project.json は、更新の前に1世代前を `project.json.bak` に残す
  - 他のタブなどで先に保存されていたら(読み込んだ時刻より新しい)、409 を返して確かめる
  - model.npz(採譜のやり直し)と score.xml(楽譜の差し替え)は、前のものがあれば確かめてから置き換える
- 書き込みは一時ファイル(`.part`)に書いてから置き換える(途中で失敗しても元のファイルが壊れない)
- 共通の関数は T03 で作る。以後のタスクの書き込みはすべてそれを使う

### 検査
- サーバーの API の検査は `tests/test_editor_*.py` に書く。`make_handler` を使い、ポート 0 で立てた
  サーバーに要求を送る。採譜モデル(torch、重み)がなくても通るように、小さな `model.npz` を検査の中で作る
- 採譜モデルや ffmpeg が要る検査は、ないときに skip する
- 検査のデータは合成した信号か、検査の中で作るファイルだけを使う(PEDB の録音はリポジトリに入れない)

### データ
- 扱う録音・楽譜は PEDB に限らない(自分で録ったピアノの録音、MuseScore から書き出した楽譜など)。
  既定値や機能の取捨は、一般の録音を基本に決める
- 録音は、採譜のための変換で音量を変えない(ベロシティの推定が録音の絶対的な音量に依存するため)

## T01 Host ヘッダの制限

目的: editor と viewer は、ブラウザから渡されたパスのファイルを読める(`/api/open`、楽譜のパス、
viewer の `file:` 指定)。127.0.0.1 で待ち受けていても、DNS リバインディング(攻撃者のドメイン名を 127.0.0.1 に
向け直す)で、ほかのページからサーバーを操作されうる。

参考: `../talk-analyzer/talk_analyzer/webutil.py` の `_host_name`、`_is_ip`、`restrict_host`

仕様
- `src/music_io/webutil.py` を作り、`host_allowed(host_header, extra_hosts=())` を置く。許すのは
  `localhost`・`127.0.0.1`・`::1`(ポート付き、`[::1]:8765` の形も)、IP アドレスそのもの、`extra_hosts`。
  それ以外と、解釈できない Host は許さない
- editor(`piano_transcribe/editor/server.py`)と viewer(`performance_analysis/viewer/server.py`)の
  `do_GET` / `do_POST` の最初で検査し、許さないときは 403 と
  「このサーバーは localhost からのアクセスだけを受け付けます(Host ヘッダが不正です)」を返す
- 両方の `serve()` に渡した `host` を `extra_hosts` に入れる(`--host mymac.local` で開けるように)

## T03 上書きしない書き込み

仕様
- `src/music_io/files.py` を作る
  - `free_name(path)`: `path` がなければそのまま、あれば `名前-2.拡張子`、`名前-3.拡張子`、… の空いている最初のもの
  - `write_bytes(path, data, overwrite=False)` / `write_text(...)` / `copy_file(src, dst, overwrite=False)`:
    `.part` に書いてから `os.replace`。`overwrite=False` で `path` があれば `FileExists`(独自の例外。
    `path`、大きさ、更新時刻、`free_name(path)` を持つ)を投げる
  - `backup(path)`: `path` があれば `path + '.bak'` に複製する(`.bak` は上書きしてよい)
- editor のサーバーで `FileExists` を受けたら、409 と `{error, exists: {path, size, mtime}, suggestion}` を返す
- 今ある書き込み箇所に当てはめる
  - `Store.save`: project.json は `backup` してから更新。読み込んだときの更新時刻(`load` の応答に `saved_mtime` を足す)
    と今の更新時刻が違えば 409(「別の画面で保存されています」)。画面では「上書き / やめて読み直す」を選ばせる
  - `Store.set_score`: score.xml がすでにあれば 409。画面で「差し替える」を選んだら `overwrite` 付きで送り直す
  - `Store.create`: 録音の複製は新しいフォルダにだけ書く(今の動作のまま。`copy_file` に置き換える)
- 画面(app.js)に、409 を受けたときの確認ダイアログを共通の関数として作る(以後のタスクでも使う)

## T04 WAV 以外の録音

参考: `../talk-analyzer/talk_analyzer/audio_utils.py` の `to_mono_wav`、`decode`

仕様
- `src/music_io/audio.py` に `convert_to_wav(src, dst)` を足す。ffmpeg で PCM 24bit の WAV にする。
  **標本化周波数とチャンネル数は元のまま、音量は変えない**(ffmpeg の `-nostdin -v error`、`-y` は使わず、

- 同じ録音のプロジェクトを探すときは、大きさではなく SHA-1 で比べる(今は大きさだけで同じとみなしている)
- 画面のファイル選択(`accept`)と README の「WAV、PCM 16/24/32bit」の記述を直す

## T10a 発音時刻の確認: サーバー側

目的: talk-analyzer の「話者交替の境界を確認」と同じく、録音の波形とスペクトログラムを拡大して、
音の発音時刻を目と耳で確かめて直せるようにする。あわせて、複数の手法の候補時刻を並べ、人が付けた時刻と比べて
どの手法が正確かを後で評価できるようにする。

参考: `../talk-analyzer/talk_analyzer/edge_check.py`(候補の手法の並べ方)、`webapp.py` の
`_spectrogram_window`、`_clip_wav`

仕様
- `src/piano_transcribe/onset_check.py` を作る(numpy だけで書く)
  - `spectrogram(x, sr, start, end, hop)`: 指定範囲の振幅スペクトログラム(対数周波数。下は A0、上は 8kHz)を
    0〜255 の濃淡で返す。窓は 2048 標本(44.1kHz で約 46ms)、hop は 1〜5ms
  - `candidates(x, sr, out, pitch, t, search=0.15)`: 時刻 `t` 付近の、音高 `pitch` の発音時刻の候補を手法ごとに返す
    - `model`: 今の音符の発音時刻(候補ではなく基準として返す)
    - `kong_peak`: モデルの発音の出力の山(`refine.find_onset` と同じ)
    - `partial_flux`: その音高の倍音(基音〜第8倍音、各 ±半音)の帯域のエネルギーの増え方の山
    - `broadband_flux`: 全帯域のエネルギーの増え方の山(和音の最初の音や打鍵の雑音)
    - 探す範囲は `t ± search`。見つからなければ None
  - 和音では、同じ時刻付近のほかの音高の倍音と重なる。`partial_flux` は、近くで鳴っているほかの音の倍音と
    重なる帯域を除いて計算する(除いた帯域の数も返す)
- サーバーに足す
  - `GET /api/projects/<名前>/spectrogram?start=&end=&hop=`: 濃淡のバイト列(T10b で描く)
  - `POST /api/projects/<名前>/onset_candidates`: `{notes, ids}` を受け、各音の候補を返す
- 録音の一部の再生は、画面がすでに録音全体を読み込んでいるので、サーバーからは切り出さない

完了条件
- [ ] `tests/test_onset_check.py`: 合成した音(倍音つきの減衰音。発音時刻を決めて作る)で、`partial_flux` と
      `broadband_flux` の候補が真の時刻から 5ms 以内。2音の和音で、片方の音高の候補がもう片方に引きずられない。
      雑音だけなら None

## T10b 発音時刻の確認: 画面

仕様
- ピアノロールの下に「発音時刻の確認」の欄を開けるようにする(閉じられる。T(キー)で開閉)
- 欄に出すもの(すべて同じ時間軸で、横に揃える)
  - 拡大した波形(画面がすでに持っている録音の標本から描く。縦の倍率を変えられる)
  - スペクトログラム(T10a)。選んだ音の倍音の位置に横の目印を引く
  - 候補の縦線(手法ごとに色を変え、凡例に手法の名前と、今の時刻との差 ms を出す)
  - 今の発音時刻(太線)と、近くのほかの音の発音時刻(細線、音名つき)
- 対象と移動
  - 対象はピアノロールで選んだ音(1音)。違いの一覧(楽譜との照合)で選んだときも、その音にする
  - 確認の対象の並び(選べる): すべての音を時刻順 / 人が追加・修正した音 / 録音に手がかりのなかった音 /
    違いのある音 / 未確認の音だけ。`.` と `,` で次・前の音へ(J/K は違いの移動に使っているため)
- 直す操作
  - 欄の中をクリックした位置を発音時刻にする。候補の線(または凡例)をクリックすると、その時刻にする
  - `←` `→` で 1ms、`Shift` 付きで 10ms 動かす(欄に焦点があるとき)
  - 発音時刻を動かしても、離鍵の時刻は動かさない(長さが変わる)。離鍵より後にはできない
  - 「判定できない」(評価から除く)の印を付けられる
  - 「確認した」の印は、時刻を直したとき・候補を選んだとき・「今のままでよい」(Enter)を押したときに付く
- 再生: 「直前 0.5 秒」「ここから 0.5 秒」「表示範囲」。録音だけ / 録音 + その音の合成音を選べる。
  再生位置を欄の中に線で示す
- 表示幅: 既定は発音時刻の前後 0.4 秒。拡大・縮小(`+` `-`、Ctrl/⌘+ホイール)、`0` で既定に戻す。最も拡大して前後 20ms
- 直した操作は、ピアノロールの元に戻す / やり直しと同じ履歴に入る

      (合成音の録音で、真の時刻の線が波形の立ち上がりと一致する)
- [ ] 手での確認: クリック・候補の選択・矢印で時刻が変わり、ピアノロールにも反映され、元に戻せる
- [ ] 手での確認: `.` `,` で並びどおりに移り、確認済みの音は「未確認の音だけ」で飛ばされる
