# 採譜モデル(Kong ら)の評価と改善の検討

2026-11-19。PEDB 2nd edition の全100演奏(42曲)。正解は Disklavier の同時記録MIDI。
数値と図は `python3 scripts/transcribe/report_kong.py` で再現でき、`output/transcription/kong_report/` に出力される
(report.md に全部の表、PNG に図。PEDB 由来なので git の管理外)。

音の対応: 同じ音高で発音時刻の差が 50ms 以内の音どうしを、差の小さい組から1対1で対応させる。
発音時刻は、演奏ごとの一定のずれ(録音とMIDIの時計の差、-60〜-1ms)を差し引いてから比べる。

## 結果のまとめ

| 項目 | 指標 | 値 |
|---|---|---|
| 音の検出 | 再現率 / 適合率 / F1 | 96.3% / 95.4% / 0.959(演奏ごとの最小 0.86) |
| 打鍵タイミング | 絶対誤差の中央値 / 90% 点 | 1.8 ms / 6.2 ms(10ms 以内 96%) |
| | 和音内の時間差(正解 10ms 以上の組) | 相関 0.70、どちらが先かの一致 97% |
| 打鍵の終わり | ペダルを離していた音(全体の17%): 推定 − 離鍵 | 中央値 −1 ms、絶対誤差の中央値 10 ms、許容内 82% |
| | ペダルを踏んでいた音: 推定 − 離鍵 | 絶対誤差の中央値 356 ms(許容内 11%)。推定は「ペダルを離して音が止んだ時刻」 |
| ベロシティ | 相関 / 平均絶対誤差(補正なし) | 0.88 / 15.4(推定が平均 +15 大きい) |
| | 演奏内の相関(velocity_z の精度) | 中央値 0.89(0.71〜0.95) |
| | 線形補正後 / 線形+音高の補正後(1曲抜き) | 平均絶対誤差 5.9 / 5.2 |
| | 和音内のベロシティの差(正解の差 10 以上) | 相関 0.86、どちらが強いかの一致 96%、差は 0.81 倍に縮む |
| ペダル | 踏んでいるかの一致(10ms ごと、CC64≥64) | F1 中央値 0.953(平均 0.900) |
| | 踏む / 離す時刻 | 中央値 +17 ms / −14 ms、絶対誤差の中央値 22 / 15 ms |

### 打鍵タイミング
- 誤差は小さく、Disklavier の記録自体の精度に近い。誤差は低音ほど、弱い音ほど大きい
  (ベロシティ 30 未満: 中央値 3.5 ms・90% 点 11.6 ms、MIDI番号 36 未満: 3.1 ms・10.1 ms)
- 和音の中の時間差(数十 ms)も、相関 0.79 で再現できる。以前の方式(guided)ではほぼ再現できなかった
- 一定のずれは −50、−30、−15、−2 ms 付近の群に分かれる。録音の回(セッション)ごとに決まると思われる。
  演奏内の相対的なタイミングを分析する限り影響はない。演奏中に時計がずれていく傾向は見られない(中央値 +0.14 ms/分)

### 抜けた音・余分な音
- 抜けた音の 98% は「その付近に推定の音がない」もの。弱い音に集中する(ベロシティ 30 未満の再現率 85.7%、45 以上は 99%)
- 余分な音: 鳴っている音の再検出 47%、倍音(1〜2オクターブ・12度上) 12%、時刻のずれ 4%、その他 37%

### 打鍵の終わり
- ペダルを使っていなければ、離鍵も約10msで推定できる
- ペダルを踏んでいると、離鍵は音にほとんど表れないため、モデルは「ペダルを離して音が止んだ時刻」を出す。
  音の終わりとして比べれば許容内 83%
- ただし、ペダルを離す前に自然に減衰して音が消えた場合などで、正解の「音の終わり」自体があいまいになる。
  ペダルを踏んでいた音の約1割は、推定が正解の音の終わりより300ms以上早い
- アーティキュレーション(音の長さの比)の分析では、ペダルを踏んでいない音に限るか、「鳴っていた長さ」として別に扱う必要がある

### ベロシティ
- 録音環境の違いで、推定値は全体に約15大きい。ただし演奏ごとの補正の傾きはほぼ1(中央値 0.97)で、
  演奏ごとに正解で補正しても(平均絶対誤差 4.9)、全体で1つの補正(5.9)と大差ない。
  つまり、同じ録音環境なら1つの補正式で足りる
- 音域による偏りがある(中央付近より低音・高音で偏る)。音高を入れた補正で 5.9 → 5.2 に下がる
- 分析で使う velocity_z(演奏内で標準化した値)の精度は、演奏内の相関で 0.89。和音内の強弱の向きは 96% 一致する

### ペダル
- 正解の CC64 は連続値で、半ペダルが多い。区切りを 64 にしたときに最もよく一致する(32: 0.905、64: 0.953、96: 0.860)
- 推定は踏むのが遅く(+17ms)、離すのが早い(−14ms)。モデルの「踏んでいる」は、CC64 で 64 より少し深い状態に相当する
- 一致が悪い演奏は、奏者 p1 のバッハ(インヴェンション)に集中する(F1 0.17〜0.55)。
  浅いペダルで、ダンパーがほとんど上がらず音にも表れない可能性がある。モデルの誤りとは言い切れない
- ソフトペダル(CC67)は推定しない

## 改善の検討

### 今すぐできる(楽譜との対応付けが不要)

| 対象 | 方法 | 見込み・確認済みの効果 |
|---|---|---|
| ベロシティ | 録音環境ごとに「線形+音高」の補正式を当てはめる | 確認済み: 平均絶対誤差 5.9 → 5.2、演奏内の相関 0.892 → 0.911(1曲抜き)。新しい録音環境では、正解つきの短い録音(数十音)が必要。分析で velocity_z だけを使うなら不要 |
| ペダル | 踏む・離す時刻の一定の補正(他の曲で求めた中央値を差し引く) | 確認済み: F1 中央値 0.953 → 0.961(1曲抜き)。効果は小さい |
| ペダル | 半ペダルの扱い: モデルのペダルの確率(フレームごと)を連続値として出し、CC64 と比べる | 半ペダルの深さがある程度わかる可能性がある。kong.py を変えて、後処理の前の確率も保存する必要がある |
| 全体 | PEDB で追加学習(1曲抜き)する | 録音環境に合わせられ、ベロシティの偏りや弱い音の検出がよくなる見込み。ただし計算資源と手間が大きく、楽譜との対応付けによる改善を見てから判断する |

### 楽譜との対応付けの後に行うほうがよい

| 対象 | 方法 | 理由 |
|---|---|---|
| 抜けた音(弱い音) | 楽譜が音を予測する時刻の近くでは、検出のしきい値を下げる(モデルの発音の確率を見て拾う) | 抜けた音の 98% は「推定がない」ものなので、楽譜という事前情報が効く。kong.py でフレームごとの確率を保存する必要がある |
| 余分な音 | 楽譜にない音のうち、鳴っている音の再検出・倍音を取り除く(装飾音は残す) | 余分な音の 6 割はこの2種類で、楽譜と照らせば判別しやすい |
| 打鍵の終わり(ペダル中) | 楽譜の音価とその場のテンポから離鍵を予測する。音からはほぼ観測できないので、推定値ではなく「事前の予測」として扱う | 音響だけでは原理的に難しい |
| ベロシティ | 楽譜上の役割(旋律・伴奏・和音の中の位置)ごとに偏りを調べ、補正するか確かめる | 和音内の強弱の差が 0.81 倍に縮む傾向がある。旋律の強調の分析に直接影響する |
| 打鍵タイミング | 楽譜上同時の音(和音)の時間差を、その場で細かく推定し直す | 今でも相関 0.79 あり、改善の余地は小さい。必要になってからでよい |

結論: 打鍵タイミングは、このまま分析に使える精度である。ベロシティは velocity_z を使えば補正なしで使え、絶対値が必要なら音高を入れた補正をする。
大きな改善が見込めるのは「抜けた弱い音」と「余分な音」で、どちらも楽譜との対応付けを前提にした方法が効く。
離鍵はペダルを踏んでいると音からほぼ観測できないので、推定を改善するより分析の側で扱いを分けるのが現実的である。
